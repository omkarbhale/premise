# Status

The owner said to build the whole of premise ([0130](decisions/0130-the-build-starts-and-covers-all-of-premise.md)). The foundation is in (configuration, storage, the work queue, a scripted agent used by tests and demos, a mock of usage-ledger, the setup check), so is the record keeper (each software's lasting record, its trace trailers and its own git repository), and so is the page with its server: start a software from an idea and walk it through the line (shown as three phases, [0165](decisions/0165-the-page-shows-three-phases.md)). The runner (starts a built software from a clean copy, confined, on a local port, restarting it if it crashes) and the reporter (reports from recorded facts only, including what failed and what was not checked) are in too ([0162](decisions/0162-how-the-runner-is-built.md)–[0164](decisions/0164-how-the-reporter-is-built.md)). The real agent runner is in too: Claude Code run headless, each session confined by its sandbox, and on by default ([0180](decisions/0180-premise-uses-real-agents-by-default.md)). So are the line engine (Why, Who, What exists, What, Say back and Plan, run by agents) and the gate (premise asks before it acts outside this machine, including creating a repository on GitHub) ([0183](decisions/0183-how-the-line-engine-is-built.md), [0182](decisions/0182-how-the-gate-is-built.md)). So are Build, Check and Run: a builder agent per task in its own working copy, a separate checker that uses the software as a user would and judges each item with evidence, and the server landing the checked commit and starting it ([0186](decisions/0186-how-build-check-and-run-are-built.md)). Intake is in, in a thin form: what you say that is not an answer, and problems or wishes reported on a software's Intake tab, are read by a triager agent against the record and mostly go onto the line as new work, sized like any piece ([0185](decisions/0185-how-intake-in-a-thin-form-is-built.md)). Existing software is in, in a thin form: bring in a repository from a folder or a clone address, and premise recovers its record from the code on its own copy, says it back for you to strike what is wrong, and asks before adding the record to your repository on a branch of its own; changes then come in as intake ([0189](decisions/0189-how-taking-on-existing-software-is-built.md)). The measures and learning from corrections are in: every report says how premise is doing (attention it took, how long things took, how often something it said worked came back as a bug), and each correction a person makes is read into a short lesson agents follow, for one software or as the operator's taste, or into an improvement for premise itself that never changes it on its own ([0193](decisions/0193-how-the-measures-are-built.md)–[0195](decisions/0195-two-kinds-of-learning.md), [learning](specs/learning.md)).
