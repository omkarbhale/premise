# 0062. Intake goes in normally; only what needs holding is held

- Status: Accepted
- Supersedes: [0041](0041-intake-can-be-held.md)
- Scope: The product
- Date: 2026-11-21
- Decided by: The owner, correcting [0041](0041-intake-can-be-held.md): "For intake: I intended to say that we don't hold most tickets, but only those that need to. Rest of the things can go in normally as we originally thought."
- Source: Old docs/decisions.md entry 62, which quotes the owner from the assistant's notes of the 2026-11-21 conversations; those notes are not kept in this repository.

## Context

- [0041](0041-intake-can-be-held.md) had recorded that much of intake can be held and analysed together.

## Decision

- Most intake is not held. It goes into the line as first intended.
- Only the items that need holding are held and read together later.

## Reason

- Owner, correcting entry 41: "For intake: I intended to say that we don't hold most tickets, but only those that need to. Rest of the things can go in normally as we originally thought."

## Alternatives considered

| Alternative | Why rejected |
| --- | --- |
| Holding much of intake by default ([0041](0041-intake-can-be-held.md)) | The owner corrected it: that was not what the owner intended. |

- **Left to the plan:** which items need holding; see [intake and reporting](../architecture/intake-and-reporting.md), [0095](0095-what-is-held.md), [0096](0096-when-held-items-are-read.md).
